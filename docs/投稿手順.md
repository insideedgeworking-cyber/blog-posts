# 投稿手順（上から投稿）

**デフォルト挙動：** ユーザーが「投稿して」など投稿を指示したら、特に順番の指定がない限り**常に `_order.json` の上（先頭）から順に**投稿する。「上から」と毎回言われなくてもこれが基準。
別の順番・特定の記事だけ、などの指定があった時のみそれに従う。

Claude Code（PC側）がこの手順で WordPress の**下書き**へ投稿する。

## 接続情報（設定済み・2026-06-02 確認）
- サイト：**https://workstartedge.com**（WorkStartEdge｜未経験から始める副業ログ / Cocoonテーマ）
- 認証：WP REST API + アプリケーションパスワードによる Basic認証（管理者 id=1 で認証OK）
- ⚠️ **必ず `https://` を使う**。`http://` だと `rest_not_logged_in` (401) になる。
- パスワードのスペースは除去して `username:password` をBase64化。
- 認証情報の実体は **`ブログアフィリエイト/wp-credentials.local.json`**（blog-postsリポジトリの外＝GitHubに上がらない）に保存。投稿時はそこから読む。アプリ（ブラウザ）には保存しない。

## 手順
1. `posts/_order.json` の `approved_order`（id配列）を読む。これが投稿順＝上から。
2. 配列の**先頭から順に**、各 `posts/post_xxx.json` を読む。
   - `status` が `approved` のものだけ対象（既に `published` ならスキップ）。
3. 本文 `body`（Markdown）を **HTMLに変換**する。
   - 見出し `##`→`<h2>`、`###`→`<h3>`、箇条書き、段落など。
   - **本文中に埋め込まれたアフィリエイトHTML（`<a>`タグ等）はそのまま残す**（変換で壊さない）。
   - 差し込み枠コメント `<!-- ▼アフィリエイト：ここに貼る▼ -->` が残っていたら、投稿前にユーザーへ確認（貼り忘れの可能性）。
4. WordPress REST API で下書きを作成：
   ```
   POST {WPサイトURL}/wp-json/wp/v2/posts
   Authorization: Basic base64(ユーザー名:アプリケーションパスワード)
   Content-Type: application/json
   {
     "title":   "<post.title>",
     "content": "<HTMLに変換した本文>",
     "status":  "draft",
     "categories": [必要なら]
   }
   ```
5. 成功したら、その記事の `status` を `published`、`wp_post_id` をレスポンスの `id` にして保存（GitHubへPUT）。
6. 次の記事へ。全部終わったら、投稿した件数とWordPress下書き一覧へのリンクを報告。

## 注意
- カテゴリ（用語/アフィリエイト等）は、必要ならWP側のカテゴリIDに対応づける（初回にマッピングを決める）。
- PR表記（広告・アフィリンクを含む記事）は本文先頭などに入っているか確認する。
- 一度にたくさん投稿する場合は、最初の1本で見え方を確認してから残りを流す。
