# ブログ記事管理システム 構成メモ

アフィリエイトブログの記事を「アイデア出し → 本文生成 → 修正 → 承認 → 投稿」まで、スマホ・PC 両方から管理するシステム。
恋愛チャンネルの台本管理システムと同じ思想（静的HTML + GitHub保存 + ブラウザから直接Claude API）。

## 公開URL
https://insideedgeworking-cyber.github.io/blog-posts/

## リポジトリ
`insideedgeworking-cyber/blog-posts`（GitHub・公開）

## なぜこの構成か
- **スマホ・PC両対応** … サーバー不要の静的HTMLをGitHub Pagesで公開。URLを開くだけ。
- **データ共有** … 記事データをGitHubリポジトリに置くので、どの端末からでも同じデータが見える。
- **AIで生成** … ブラウザから直接 Claude API を呼んで本文を生成・修正。
- **安全** … WordPressのパスワードはアプリに置かない。投稿はPC側のClaude Codeが担当。

## ファイル構成
```
blog-posts/
├─ index.html              … アプリ本体（UI・生成・保存の全ロジック）
├─ posts/
│  ├─ post_xxx.json        … 記事データ（1ファイル＝1記事＝1投稿）
│  ├─ _order.json          … 承認済みの投稿順（approved_order）
│  └─ schema.json          … データ形式の定義
├─ docs/
│  ├─ システム構成.md       … このファイル
│  └─ 記事作成ガイド.md      … 文章方針・修正メモ・SEO対策（生成時に自動参照）
└─ README.md
```

## 記事データの形式（post_xxx.json）
| フィールド | 内容 |
|---|---|
| `id` | `post_001` など |
| `created_at` | 作成日 |
| `theme` | テーマ（何についての記事か） |
| `ideas` | 盛り込みたい要素のメモ |
| `title` | 記事タイトル |
| `category` | アフィリエイト / 用語 / ノウハウ / ツール紹介 / 比較 / 体験談 / その他 |
| `keywords` | SEOキーワード（配列） |
| `body` | 本文（Markdown） |
| `char_count` | 文字数 |
| `status` | `idea`→`drafting`→`approved`→`published` |
| `wp_post_id` | WordPress下書きのID（投稿後にセット） |
| `notes` | メモ |

## 画面・機能
- **＋新規テーマを追加** … テーマ・アイデア・カテゴリ・キーワードを入力
- **💡アイデア&生成** … 入力内容＋『記事作成ガイド.md』を元にClaudeが本文生成
- **✏️編集** … 本文を直接編集 ／ 全文コピー ／ 「🔧修正指示」でClaudeに直させる
- **👁プレビュー** … Markdownを記事の見た目で表示。ステータス・メモ変更
- **タブ** … 全て / 💡アイデア / ✍️作成中 / ✅承認済 / 📤投稿済
- **✅承認済タブ** … 投稿順に並び替え（PC=ドラッグ / スマホ=↑↓）。順番は `_order.json` に保存
- **⚙️設定** … Anthropic API Key / GitHub Token / 生成モデル（端末ごとにlocalStorage保存）

## 投稿フロー（WordPressへの下書き出し）
1. アプリで記事を `✅承認済` にして、投稿したい順に並べる
2. PCのClaude Codeに「**上から投稿して**」と指示
3. Claude Codeが `_order.json` の順に各記事を読み、WordPressの**下書き**へ作成
4. 各記事の `status` を `published`、`wp_post_id` をセットして保存
   - 投稿には WordPressサイトURL ＋ アプリケーションパスワード（WP REST API）を使用予定
   - 認証情報はアプリに保存せず、PC側でのみ扱う

## 台本管理システムとの独立性
- 別フォルダ・別リポジトリ（台本=`inside-edge-scripts`、ブログ=`blog-posts`）
- 保存先JSONも別（`scripts/` と `posts/`）
- ブラウザ設定キーも別名（台本=`anthropic_key`/`github_token`、ブログ=`blog_anthropic_key`/`blog_github_token`/`blog_model`）
- → 互いに一切影響しない
