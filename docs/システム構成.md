# ブログ記事管理システム 構成メモ

アフィリエイトブログの記事を「アイデア出し → 本文生成 → 修正 → 承認 → 投稿」まで、スマホ・PC 両方から管理するシステム。
恋愛チャンネルの台本管理システムと同じ思想（静的HTML + GitHub保存 + ブラウザから直接Claude API）。

## 公開URL
https://insideedgeworking-cyber.github.io/blog-posts/

## リポジトリ
`insideedgeworking-cyber/blog-posts`（GitHub・公開）

## なぜこの構成か
- **スマホ・PC両対応** … サーバー不要の静的HTMLをGitHub Pagesで公開。URLを開くだけ。
- **データ共有** … 記事データをGitHubリポジトリに置くので、どの端末からでも同じデータが見える。
- **AIで生成** … ブラウザから直接 Claude API を呼んで本文を生成・修正。
- **安全** … WordPressのパスワードはアプリに置かない。投稿はPC側のClaude Codeが担当。

## ファイル構成
```
blog-posts/
├─ index.html              … アプリ本体（UI・生成・保存の全ロジック）
├─ posts/
│  ├─ post_xxx.json        … 記事データ（1ファイル＝1記事＝1投稿）
│  ├─ _order.json          … 並び順（manual_order=全体の手動順 / approved_order=投稿順）
│  ├─ _glossary.json       … 用語クロスリンクの定義（用語→アンカー）
│  ├─ affiliates.json      … アフィリ素材（アプリ🔗で登録）
│  └─ schema.json          … データ形式の定義
├─ images/                 … 記事の図・グラフ・表紙（PNG。投稿時にWPメディアへ複製）
├─ tools/                  … 投稿・図生成のpythonスクリプト（下記「運用ツール」）
├─ docs/
│  ├─ システム構成.md       … このファイル（構成＋修正履歴）
│  ├─ 記事作成ガイド.md      … 文章方針・修正メモ・SEO対策（生成時に自動参照）
│  ├─ site-custom.css      … サイトのデザインCSS（WPカスタマイザーに手動で貼る用のバックアップ）
│  └─ ネタ帳.md / 執筆ルール.md / 投稿手順.md
└─ README.md
```

※ WordPress認証情報 `wp-credentials.local.json` はリポジトリの**1つ上の階層**（`ブログアフィリエイト/`）に置き、GitHubには上げない。

## 記事データの形式（post_xxx.json）
| フィールド | 内容 |
|---|---|
| `id` | `post_001` など |
| `created_at` | 作成日 |
| `theme` | テーマ（何についての記事か） |
| `ideas` | 盛り込みたい要素のメモ |
| `title` | 記事タイトル |
| `category` | アフィリエイト / 用語 / ノウハウ / ツール紹介 / 比較 / 体験談 / その他 |
| `keywords` | SEOキーワード（配列） |
| `body` | 本文（Markdown） |
| `char_count` | 文字数 |
| `status` | `idea`→`drafting`→`approved`→`published` |
| `wp_post_id` | WordPress記事のID（投稿後にセット。あれば次回は上書き更新） |
| `excerpt` | メタ説明（検索結果のスニペット用・120字目安）|
| `notes` | メモ（社内用・記事には出ない） |

## 画面・機能
- **＋新規テーマを追加** … テーマ・アイデア・カテゴリ・キーワードを入力
- **💡アイデア&生成** … 入力内容＋『記事作成ガイド.md』を元にClaudeが本文生成
- **✏️編集** … 本文を直接編集 ／ 全文コピー ／ 「🔧修正指示」でClaudeに直させる
- **👁プレビュー** … Markdownを記事の見た目で表示。ステータス・🔎メタ説明（excerpt）・メモを編集
- **タブ** … 全て / 💡アイデア / ✍️作成中 / ✅承認済 / 📤投稿済
- **並び替え（全タブ対応）** … PC=ドラッグ&ドロップ / スマホ=▲▼。全体順は `_order.json` の `manual_order`、承認済の順（投稿順）は `approved_order` として自動保存
- **カードのステータス変更** … 各カードのプルダウンで 💡→✍️→✅→📤 をその場で変更・保存
- **修正指示の保持** … 「🔧修正指示」はlocalStorageに保存され、再読込やタブ離脱で消えない
- **⚙️設定** … Anthropic API Key / GitHub Token / 生成モデル（端末ごとにlocalStorage保存）

## 投稿フロー（WordPressへ・tools/post_to_wp.py が担当）
投稿・更新は手作業ではなく **`tools/post_to_wp.py`** を使う。

```
python tools/post_to_wp.py post_006 --status publish   # 公開（draftで下書きも可）
python tools/post_to_wp.py post_006 --dry              # 投稿せず変換結果を確認
```

このツールが自動でやること：
1. 本文Markdown → HTML 変換（`##`/`**`/`-`/`>`/`![]()`/アフィリ枠`<!-- -->`コメント温存）
2. **本文の画像をWordPressメディアへアップロード**し、URLを自前ドメインに差し替え（同名は再利用＝重複しない）
3. **メタ説明（excerpt）** をWordPressへ送信（検索スニペット用）
4. **用語クロスリンク**（下記）を自動付与
5. カテゴリを名前から検索／無ければ自動作成
6. `wp_post_id` があれば**更新**、無ければ新規作成

投稿後、`post_xxx.json` の `wp_post_id` と `status` を更新してコミット。
- 認証は `wp-credentials.local.json`（リポジトリ外・非公開）。**JSONはBOM付きなので utf-8-sig で読む。**

## 用語クロスリンク（プラグイン不使用＝素のHTMLリンク）
他の記事で**初めて出てきたPC用語**を、用語解説記事（post_002）の該当箇所へ自動リンクする仕組み。
- 定義は `posts/_glossary.json`（`{glossary_post_id, url, terms:[{slug, match, aliases}]}`）。**用語を足したいときはここに追記**するだけで全記事に効く。
- `post_to_wp.py` が、用語解説記事の見出しに飛び先アンカー `id="g-<slug>"` を付与し、他記事では初出の用語（最初の1回）をその解説へリンクする（見出し/画像/既存リンク行は除外、長い語を優先）。

## サイトデザイン
- 配色：青基調 `#2f6fb3` ＋ オレンジ差し色 `#ff7a3d` ＋ 薄グレー背景 `#e7edf5`。
- CSSの本体は **WordPress カスタマイザー → 追加CSS** に手動で貼る（`docs/site-custom.css` がバックアップ）。
- **追加CSSはREST APIで書けない／ウィジェットの`<style>`はKSESで除去される** → CSS変更はカスタマイザーに手で貼る（貼ったら左上の「公開」ボタンを押す。押し忘れに注意）。
- Cocoonの主なセレクタ：ヘッダー`#header-container` / サイト名`.site-name-text-link` / ナビ`#navi` / 本文`.entry-content` / 一覧カード`.entry-card-wrap`。

## 台本管理システムとの独立性
- 別フォルダ・別リポジトリ（台本=`inside-edge-scripts`、ブログ=`blog-posts`）
- 保存先JSONも別（`scripts/` と `posts/`）
- ブラウザ設定キーも別名（台本=`anthropic_key`/`github_token`、ブログ=`blog_anthropic_key`/`blog_github_token`/`blog_model`）
- → 互いに一切影響しない
